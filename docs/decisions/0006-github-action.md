# 0006: The GitHub Action

Status: draft by Claude Code for Aditya to rewrite. Date: 2026-11-21.

## Chosen

1. **`verimend fix --open-pr` does the work; the Action only runs it.** The pull request, the comment and the guards live in `verimend/github.py`, under test. The Action (`action/action.yml`) is a thin composite: a guard step, Python, VeriMend installed with `uv sync --frozen` from its own `uv.lock`, then `verimend fix --open-pr`. The same command works from a laptop with `GITHUB_TOKEN` set.
2. **A verified fix becomes a pull request from `verimend/fix-<short sha>`** into the branch that failed.
   - The diff is committed in a separate git worktree, so the checkout itself is never touched.
   - Only that branch is pushed.
   - The body has SPEC §10's five sections and says a person must review it.
   - In Actions the commit is by `github-actions[bot]`; locally, by whoever runs it.
3. **Anything else posts the diagnosis as a comment** (with Aditya): on the failing pull request, or else on the failing commit. It covers escalated, not fixed and stopped by a cap. Nothing is pushed.
4. **Guards, each with a test that proves it blocks:**
   - only a `verimend/fix-*` branch can be pushed, never the default branch or the failing one;
   - an empty diff pushes nothing;
   - a pull request from a fork, a run on VeriMend's own fix branch, and a detached checkout are all refused before the agent starts, so nothing is spent.
   - The Action's guard step skips forks and fix branches before installing anything.
5. **The API key reaches one step.** It is passed as an environment variable to the step that runs VeriMend, and nowhere else.
6. **GitHub's REST API through `urllib`.** No new dependency for three calls: read the default branch, open a pull request, post a comment.
7. **History in the sandbox.** When the project is the root of a git repository, `verimend fix` copies `.git` into its sandbox. That way `inspect_history` can find the commit that broke the build; in both demo runs it did. The verifier still ignores `.git`.
   - This changes what a tool sees, not the tool's code, prompt or hooks, so `agent-v1` is unchanged. The fault suite already worked this way.
   - A project inside a larger repository gets no history.
8. **The demo repository** (`adikan2k/verimend-demo`, private, with Aditya).
   - It is generated by `scripts/make_demo_repo.py` from `demo/`, with the dbt project at the root.
   - Its broken commits are pushed to its `main` by Claude Code on purpose. The agent itself only ever pushes `verimend/fix-*`.
   - Two settings were needed. verimend's Actions access is set to "repositories owned by adikan2k", so a private repo can use the Action. The demo repo allows GitHub Actions to create pull requests; without that, GitHub refuses the pull request.

## What the runs showed

[`bench/results/action-demo-2026-11-21`](../../bench/results/action-demo-2026-11-21/README.md):

- **Logic bug** ("Update order totals", `sum` to `max`): [demo pull request #1](https://github.com/adikan2k/verimend-demo/pull/1), restoring `sum(amount)`.
  - The verifier passed it on the first attempt. It cost $0.0035 over 18 steps and 54 s.
  - Checked by hand: the fix branch builds all 39 nodes, and every model equals the clean project's build.
- **Bad data** ("Load the November payments export", three negative payments): escalated as `bad_data`, with the diagnosis on the commit and no branch pushed. It cost $0.0037 over 17 steps and 31 s.
  - The diagnosis names the three rows.
  - It shows the orders behind them were not returned, so no refund explains them.
  - It says the fix belongs with whoever owns the export.
- GitHub started a CI run on the fix pull request but holds it as "action required": a person has to approve workflows triggered by the Actions bot. Nothing failed.
- **Spend:** $0.0072.

## Rejected

- **Logic in the workflow YAML** (shell steps calling `gh`). It is harder to test, and it would not work outside Actions.
- **Third-party setup actions** (such as `astral-sh/setup-uv`). Only first-party actions are used; uv comes from pip at a pinned version.
- **`pull_request_target`.** It would hand secrets to code from forks.
- **An issue per failure** instead of a commit comment. Issues pile up for a bot that runs on every red build.
- **Making the repositories public now.** That is Aditya's call, probably in phase 8. Private repositories work with the access setting.
